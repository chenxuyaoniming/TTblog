### JS 设计模式

常用模式与场景如下；与框架结合时，**观察者 / 发布订阅** 对应 Vue 响应式、Redux 订阅，**单例** 对应全局配置、日志实例。

---

#### 创建型

| 模式 | 要点 | 前端场景 |
| ---- | ---- | -------- |
| **单例** | 全局唯一实例 | 弹窗管理器、全局配置、埋点 SDK |
| **工厂** | 封装创建逻辑，返回统一接口 | 根据类型创建不同图表组件、不同请求适配器 |

---

#### 结构型

| 模式 | 要点 | 前端场景 |
| ---- | ---- | -------- |
| **装饰器** | 动态扩展功能（ES 提案 / TS / Babel） | 高阶组件 HOC、`@connect`、日志/权限包装 |
| **适配器** | 转换接口以兼容旧代码 | 新老 API 映射、第三方 SDK 封装 |

---

#### 行为型

| 模式 | 要点 | 前端场景 |
| ---- | ---- | -------- |
| **观察者** | 目标与观察者直接依赖 | 数据变 → 通知多个监听者 |
| **发布订阅** | 中间事件总线解耦 | `EventEmitter`、跨组件通信（慎用全局 bus） |
| **策略** | 封装可替换算法 | 表单校验规则、支付方式、主题切换 |

---

#### 使用建议

不必强行套用名词；**可读、可测、边界清晰**优先。若模式增加间接层却无收益，应简化。
